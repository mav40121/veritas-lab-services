# VeritaCheck method-comparison demo video — recording-prep package

Parking-lot #38. Prepared 2026-10-04. Owner: Michael Veri.

This is the agent-deliverable half of #38: storyboard, click-by-click script,
demo-lab pre-fill state, on-screen caption text, and post-production checklist.
The recording itself is operator work: roughly one hour with Loom, ScreenPal,
OBS, or Camtasia, including a second take. The agent cannot drive a live screen
recording, which is why this item parks here until you sit down to record.

Goal of the piece: prove the "an experienced lab tech figures it out in seconds"
claim. 30 to 60 seconds, from a blank Correlation / Method Comparison study to a
finished report PDF. No voiceover, no narration, visible cursor motion, captions
burned in post. Embed autoplay-muted on the marketing site; attach to conference
follow-up emails.

The product labels used below are the real ones in the current VeritaCheck UI
(New Study, Correlation / Method Comparison, Analyte, Instrument, TEa, Create
Study, Generate Report). Confirm each against the live screen before recording in
case a label moved.

## 1. Pre-flight (do this before you hit record)

- **Account/lab:** record on your own demo lab, never a client account. Riverside
  Regional Medical Center (CLIA 22D0999999) is the demo fixture identity. Confirm
  the header shows Riverside and the demo CLIA, not a real lab.
- **Clean window:** full-screen the browser. Close other tabs so the tab strip is
  not a giveaway. Hide bookmarks bar. Use a clean browser profile with no
  personal extensions visible.
- **Zoom:** set browser zoom so the data grid and the TEa/result read large on a
  1080p capture. Roughly 110 to 125% usually reads best; check against your
  capture resolution.
- **Cursor:** turn on cursor highlighting in your capture tool if it has it
  (ScreenPal and Camtasia do). The claim is "watch a tech do it," so the cursor
  is the narrator.
- **Data ready to paste:** have the paired results (below) on the clipboard or in
  a scratch note so the paste is one motion, not typing. Typing kills the "in
  seconds" feel.
- **Do a dry run once** without recording so the first real take is clean.

## 2. Demo-lab pre-fill state (what should already exist before the take)

Keep the pre-fill minimal so the take shows the real work, not setup. Before
recording, the demo lab should have:

- Lab identity set to Riverside Regional Medical Center, CLIA 22D0999999, with a
  medical director name on file (so the generated PDF signature block is
  populated and page 1 looks complete).
- At least one instrument already on the menu so the Instrument field has a
  selectable value and you are not shown creating an instrument mid-take.
- No half-finished method-comparison study sitting in the list that could be
  confused with the one you create on camera. Start from an empty or tidy study
  list.

Everything else (the study itself, the analyte, the data) gets created live on
camera. That is the point of the video.

**Paired data to paste (glucose, mg/dL, realistic method-comparison set):**

Use a real, defensible dataset you already trust from your own files. Do NOT let
the agent invent measurement values for a published asset. If you want a quick
set from your own verification records, drop it in and the storyboard below still
holds. The take needs roughly 20 to 40 paired points for the regression to look
real and land inside TEa.

## 3. Storyboard (the 6 beats, ~60 seconds)

| # | Beat | On screen | ~sec |
|---|------|-----------|------|
| 1 | Start blank | VeritaCheck studies list, then the New Study button | 0-6 |
| 2 | Pick the study type | Study type picker, choose Correlation / Method Comparison | 6-14 |
| 3 | Name it | Enter Analyte (e.g. Glucose), pick the Instrument, confirm units and TEa populate | 14-24 |
| 4 | Paste the data | One paste into the data grid, grid fills with paired points | 24-36 |
| 5 | Create + result | Create Study, the regression/stats and the pass-against-TEa result render | 36-48 |
| 6 | Finished PDF | Generate Report, the report PDF opens with the signature block on page 1 | 48-60 |

End on the finished PDF held for a beat, then cut to the CTA card (section 5).

## 4. Click-by-click script

1. Land on the VeritaCheck studies list. Pause half a second so the viewer sees
   the starting point. Move cursor to **New Study** and click.
2. In the study-type choice, click **Correlation / Method Comparison**. (Do not
   use "Method Comparison" alone anywhere on screen; the full label is the
   standard.)
3. In the **Analyte** field, type the analyte name (e.g. Glucose). Select or
   confirm the **Instrument**. Let units and **TEa** populate from the analyte;
   pause so the viewer sees the allowable total error appear on its own. That
   auto-populated TEa is a quiet proof point, so give it a beat.
4. Click into the data grid and paste the paired results in one motion. The grid
   fills. Do not type cell by cell.
5. Click **Create Study**. The results render: the regression line, the stats,
   and the determination against CLIA TEa. Let the pass result sit on screen for
   a full second or two. This is the payoff beat.
6. Click **Generate Report**. When the PDF opens, scroll once, slowly, to show
   page 1 carries the results, the narrative, and the signature block together.
   Hold on the finished page.
7. Stop recording. Do not show the download dialog or the file system.

If any step stalls on the take, stop and restart from beat 1 rather than editing
around a hitch. A clean single run is the asset.

## 5. On-screen caption text (burn in during post, no voiceover)

Keep captions short, lowercase-friendly, one line each, timed to the beat.
No em dashes. Suggested:

- Beat 1: "start a new study"
- Beat 2: "method comparison"
- Beat 3: "pick the analyte. allowable error fills in."
- Beat 4: "paste your paired results"
- Beat 5: "one click. result against CLIA TEa."
- Beat 6: "surveyor-ready PDF, signature on page one"

End card text (static, 3 to 4 seconds):
- Line 1: "VeritaCheck(TM)"
- Line 2: "method verification without the spreadsheet"
- Line 3: "www.veritaslabservices.com/demo"

Trademark and URL rules apply to the end card because it is public-facing: the
trademark mark on VeritaCheck, www form of the URL, no hash route, no em dashes.

## 6. Post-production checklist

- [ ] Crop to the content area; remove any OS chrome, clock, or tab strip that
      leaked into the frame.
- [ ] Blur or mask any CLIA number if a real one is visible. The demo CLIA
      (22D0999999) is safe to show; a real lab CLIA is not.
- [ ] Confirm no real patient data, no real lab name, no client identity anywhere
      in the frame across all 60 seconds. Step through frame by frame around the
      PDF beat.
- [ ] Burn in the captions from section 5, timed to the beats.
- [ ] Add the end CTA card (section 5 text).
- [ ] Export autoplay-muted friendly: no reliance on audio, since the site embed
      and email use play muted.
- [ ] Two exports: a web embed version (looped or single-play, muted) and an
      email-friendly version (link to hosted copy; most email clients will not
      autoplay inline).
- [ ] Final QC pass: watch it once at full size as a stranger would. If the "in
      seconds" claim does not land, re-record rather than ship a slow take.
